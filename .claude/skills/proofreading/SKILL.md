# Skill: Professional Proofreading & Editing

## Purpose

This skill provides systematic patterns for professional editing that improves clarity, correctness, and consistency while preserving the author's voice and intent. It transforms rough drafts into polished, publication-ready content.

## When to Use

Use this skill when:
- Proofreading for grammar and punctuation errors
- Improving clarity and readability
- Enforcing style guidelines and brand voice
- Ensuring consistency in terminology and tone
- Polishing content before publication
- Structural editing for better flow

**Trigger scenarios**: "proofread this", "edit for clarity", "check grammar", "polish this writing", "enforce style guide"

## Prerequisites

- Content to be edited
- Audience and purpose understood
- Style guidelines available (if any)
- Context about intended tone/voice

## Core Proofreading Process

### Step 1: Initial Assessment

**Goal**: Understand content and editing needs

**Actions**:
1. Identify content parameters:
   - **Type**: Technical doc, blog post, marketing copy, email, report?
   - **Audience**: Technical experts, general public, executives, customers?
   - **Purpose**: Inform, persuade, instruct, entertain?
   - **Formality**: Formal, professional, casual, friendly?
   - **Length**: Constraints or targets?

2. Check style guidelines:
   - Read CLAUDE.md for brand voice
   - Check project-specific style guides
   - Note special requirements

3. Initial read-through:
   - Understand main message
   - Note overall tone
   - Identify major issues
   - Assess scope of work needed

**Quality Check**:
- [ ] Content type and audience clear
- [ ] Style guidelines reviewed
- [ ] Initial assessment complete
- [ ] Editing scope understood

### Step 2: Comprehensive Editing

**Goal**: Apply systematic editing checklist

**The 5-Category Checklist**:

#### A. Grammar & Mechanics

- [ ] **Subject-verb agreement**
  - ✅ "The team is working" (collective noun, singular verb)
  - ❌ "The team are working" (UK English exception)

- [ ] **Verb tense consistency**
  - ✅ "She walked to the store and bought milk" (both past)
  - ❌ "She walked to the store and buys milk" (mixed tenses)

- [ ] **Pronoun-antecedent agreement**
  - ✅ "Each developer has their workspace" (singular they)
  - ❌ "Each developer have their workspace"

- [ ] **Article usage (a/an/the)**
  - ✅ "an hour", "a user", "the API"
  - ❌ "a hour", "an user"

- [ ] **Punctuation**
  - Commas: serial/Oxford comma, after introductory phrases
  - Periods: end of sentences, abbreviations
  - Semicolons: joining related clauses
  - Colons: introducing lists or explanations
  - Apostrophes: possessive vs. contraction

- [ ] **Apostrophes**
  - ✅ "it's" (it is), "its" (possessive)
  - ✅ "the user's account" (singular possessive)
  - ✅ "the users' accounts" (plural possessive)

- [ ] **Capitalization**
  - Proper nouns, sentence starts, headings
  - Consistent heading style (Title Case or Sentence case)

- [ ] **Spelling**
  - Check all words
  - Consistent variant (US vs. UK English)

- [ ] **Homophones**
  - their/there/they're
  - your/you're
  - its/it's
  - to/too/two
  - affect/effect

#### B. Clarity & Readability

- [ ] **Active voice preferred**
  - ✅ "The team created the feature" (active, clear)
  - ❌ "The feature was created by the team" (passive, wordier)
  - Exception: Passive OK when actor unknown or unimportant

- [ ] **Concise language**
  - ❌ "Due to the fact that" → ✅ "Because"
  - ❌ "In order to" → ✅ "To"
  - ❌ "At this point in time" → ✅ "Now"

- [ ] **Strong, specific verbs**
  - ❌ "make improvements" → ✅ "improve"
  - ❌ "give consideration to" → ✅ "consider"
  - ❌ "is able to" → ✅ "can"

- [ ] **Short sentences**
  - Target: 15-20 words average
  - Vary length for rhythm
  - Break complex sentences

- [ ] **Paragraph length**
  - Target: 3-5 sentences
  - One main idea per paragraph
  - Use whitespace for breathing room

- [ ] **Transitions**
  - Connect ideas between sentences
  - Connect paragraphs logically
  - "However", "Therefore", "Additionally"

- [ ] **Jargon**
  - Define technical terms for general audience
  - Use simpler alternatives when possible
  - Consistent terminology

- [ ] **Eliminate ambiguity**
  - ❌ "The manager told the employee he was promoted"
  - ✅ "The manager told the employee that the employee was promoted"

#### C. Structure & Flow

- [ ] **Logical order**
  - Ideas flow naturally
  - No jumps in logic
  - Progressive disclosure (simple → complex)

- [ ] **Headings**
  - Descriptive and clear
  - Consistent hierarchy (# ## ###)
  - Parallel structure
  - No orphan headings (heading with no content)

- [ ] **Paragraphs**
  - One main idea per paragraph
  - Topic sentence first (usually)
  - Supporting details follow
  - Concluding sentence (sometimes)

- [ ] **Lists**
  - Use bullets for unordered items
  - Use numbers for sequential steps
  - Parallel structure in all items
  - Punctuation consistent

- [ ] **Introduction**
  - Sets context
  - States purpose
  - Previews structure (if long doc)

- [ ] **Conclusion**
  - Summarizes key points
  - Provides closure
  - Call-to-action (if appropriate)

- [ ] **Formatting**
  - Consistent and appropriate
  - Enhances readability
  - Not distracting

#### D. Tone & Style

- [ ] **Consistent tone**
  - Formal, professional, casual, friendly (pick one)
  - Maintained throughout
  - Appropriate for audience and purpose

- [ ] **Brand voice** (if applicable)
  - Matches guidelines (CLAUDE.md)
  - Consistent with organization's style
  - Reinforces brand identity

- [ ] **Person**
  - First (I/we), second (you), third (he/she/they)
  - Consistent choice throughout
  - Appropriate for context

- [ ] **Contractions**
  - Use in informal writing (can't, don't)
  - Avoid in formal writing (cannot, do not)
  - Consistent within document

- [ ] **Inclusivity**
  - Gender-neutral language
  - Culturally sensitive
  - Accessible terminology
  - Avoid assumptions

- [ ] **Professional**
  - No unnecessary slang
  - Appropriate level of formality
  - Respectful tone

- [ ] **Emotional tone**
  - Enthusiasm, urgency, calm (match purpose)
  - Not manipulative
  - Authentic

#### E. Consistency

- [ ] **Terminology**
  - Same terms for same concepts
  - "user" throughout (not user/customer/client mix)
  - Build term list if needed

- [ ] **Spelling variants**
  - US English (color, realize) OR
  - UK English (colour, realise)
  - Pick one, use consistently

- [ ] **Date formats**
  - MM/DD/YYYY or DD/MM/YYYY or YYYY-MM-DD
  - Consistent throughout

- [ ] **Number formatting**
  - "5" vs. "five" (pick convention)
  - Usually: Spell out 1-10, numerals for 11+
  - Exception: Technical writing often uses numerals

- [ ] **Hyphenation**
  - "email" vs. "e-mail" (email is modern standard)
  - Consistent compound words

- [ ] **Abbreviations**
  - Spell out first use, then abbreviation
  - "Application Programming Interface (API)"
  - Then: "API" throughout

- [ ] **List formatting**
  - Parallel structure in all items
  - "Create, edit, and delete" (all verbs)
  - ❌ "Create, editing, and deletion" (mixed)

### Step 3: Deep Clarity Pass

**Goal**: Improve readability and understanding

**Common Clarity Improvements**:

**1. Passive to Active**:
```
❌ "The report was written by the team"
✅ "The team wrote the report"
```

**2. Eliminate Nominalizations**:
```
❌ "We need to make a determination"
✅ "We need to determine"

❌ "The implementation of the solution"
✅ "Implementing the solution"
```

**3. Remove Redundancy**:
```
❌ "final outcome" → ✅ "outcome"
❌ "past history" → ✅ "history"
❌ "advance planning" → ✅ "planning"
❌ "completely eliminate" → ✅ "eliminate"
```

**4. Strengthen Weak Constructions**:
```
❌ "There are many benefits"
✅ "Many benefits exist" or "Benefits include..."

❌ "It is important to note that"
✅ "Note that" or just state the point
```

**5. Replace Vague Words**:
```
❌ "very good" → ✅ "excellent" or quantify
❌ "a lot of" → ✅ "many", "significant", or specific number
❌ "things" → ✅ specific nouns
```

**6. Simplify Complex Sentences**:
```
❌ "The system, which was designed to handle large volumes of data, and which has been in use for several years, needs updating."

✅ "The data processing system has been in use for several years. It needs updating."
```

### Step 4: Change Tracking

**Goal**: Document all edits systematically

**Actions**:
1. Track changes by category:
   - Grammar & punctuation fixes
   - Clarity improvements
   - Style adjustments
   - Structural changes

2. For major changes:
   - Show before/after
   - Explain rationale
   - Note alternatives considered

3. Build change summary:
   - Count changes by category
   - Highlight significant edits
   - Note patterns (repeated errors)

**Change Summary Template**:
```markdown
## Editing Summary

**Total Changes**: 47

### Grammar & Punctuation (18 changes)
- Fixed subject-verb agreement (5 instances)
- Corrected comma usage (8 instances)
- Fixed spelling errors (3 instances)
- Corrected apostrophe usage (2 instances)

### Clarity & Readability (21 changes)
- Converted to active voice (7 sentences)
- Simplified complex sentences (6 instances)
- Removed redundancy (5 phrases)
- Clarified ambiguous references (3 instances)

### Style & Consistency (8 changes)
- Enforced consistent terminology (4 terms)
- Applied brand voice guidelines
- Standardized heading format
- Ensured inclusive language

## Major Changes

### 1. Paragraph 3: Simplified Technical Explanation

**Before**: "The utilization of the aforementioned methodology enables the facilitation of enhanced performance metrics through the optimization of resource allocation mechanisms."

**After**: "This method improves performance by optimizing how we allocate resources."

**Rationale**: Original was unnecessarily complex. Simplified without losing meaning.
```

### Step 5: Final Validation

**Goal**: Ensure edited content meets all standards

**Final Checklist**:
- [ ] Read edited version start to finish
- [ ] Flow and coherence check
- [ ] Meaning preserved from original
- [ ] All errors corrected
- [ ] Style guide followed
- [ ] Tone appropriate for audience
- [ ] Word count (if constraint exists)
- [ ] Format requirements met

**Quality Metrics**:
- ✅ **Correctness**: No grammar/spelling errors
- ✅ **Clarity**: Easy to understand
- ✅ **Consistency**: Uniform throughout
- ✅ **Tone**: Appropriate for audience
- ✅ **Preservation**: Author's intent maintained

## Style Guide Quick Reference

### MyClaude Framework Style (from CLAUDE.md)

- **Tone**: Professional, clear, non-fluffy
- **Structure**: Headings, bullets, short paragraphs
- **Format**: Markdown with proper syntax
- **Voice**: Active, direct, respectful
- **Contractions**: Allowed in informal context
- **Person**: Second person ("you") for user-facing

### Common Style Rules

- **Oxford comma**: ✅ Use it ("red, white, and blue")
- **Headings**: Sentence case ("Getting started with MyClaude")
- **Code**: Inline with \`backticks\`, blocks with triple backticks
- **Emphasis**: **Bold** for strong, *italic* for mild
- **Lists**: Parallel structure, consistent punctuation

## Editing Patterns by Content Type

### Technical Documentation
- Accuracy critical
- Clear step-by-step instructions
- Define all technical terms
- Include code examples
- Test instructions

### Marketing Copy
- Engaging and persuasive
- Benefit-focused
- Active voice strongly preferred
- Conversational tone (usually)
- Strong calls-to-action

### Business Reports
- Formal and professional
- Data-driven
- Executive summary upfront
- Clear recommendations
- Supporting evidence

### Blog Posts
- Conversational but professional
- Personal voice acceptable
- Storytelling welcome
- Section headings for scanning
- Clear takeaway

## Common Errors and Fixes

### Comma Splices
```
❌ "The test passed, the feature is ready"
✅ "The test passed. The feature is ready."
✅ "The test passed, so the feature is ready."
✅ "The test passed; the feature is ready."
```

### Run-on Sentences
```
❌ "We tested the feature and it worked well and users liked it and we decided to ship it"
✅ "We tested the feature, and it worked well. Users liked it, so we decided to ship it."
```

### Misplaced Modifiers
```
❌ "Walking down the street, the building looked tall"
✅ "Walking down the street, I thought the building looked tall"
```

### Subject-Verb Distance
```
❌ "The system, despite its complexity and the many features it contains, work well"
✅ "The system works well despite its complexity and many features"
```
